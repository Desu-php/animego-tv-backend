# API для Android / Google TV

Запустите backend: `go run ./cmd/api` или `docker compose up --build`.
Откройте [Swagger UI](http://localhost:8080/swagger/index.html).
Контракт [openapi.json](openapi.json) можно импортировать в инструменты API
или использовать для генерации клиента. Документация включает все шесть
эндпоинтов, модели, параметры и публичные ошибки текущего backend.

## Адрес backend

На компьютере используйте `http://localhost:8080/`. На физическом TV задайте
`http://<LAN-IP-компьютера>:8080/`: `localhost` на TV означает сам телевизор.
Устройство должно иметь сетевой доступ к компьютеру и порту backend.
Для Android Emulator адрес хоста обычно `http://10.0.2.2:8080/`.

Добавьте Android-разрешение `android.permission.INTERNET`. Для локальной
разработки через HTTP разрешите cleartext-трафик в debug-конфигурации приложения.
При публикации backend используйте HTTPS. Авторизация в текущем API отсутствует.

## Переход от поиска к видео

1. `GET /api/v1/anime/search?q=solo`: покажите `data` как карточки поиска.
   Запрос очищается от пробелов по краям; допустимы 1–200 Unicode-кодовых точек.
2. `GET /api/v1/anime/{id}`: откройте карточку аниме.
3. `GET /api/v1/anime/{id}/episodes`: покажите доступные серии. Используйте
   этот список для выбора серии; `episode_count` может включать запланированные.
4. `GET /api/v1/anime/{id}/episodes/{episodeID}/translations`: покажите
   переводы и их `players`. Поддерживаются `provider`: `aniboom`, `kodik`, `cvh`.
5. `GET /api/v1/anime/{id}/episodes/{episodeID}/players/{playerID}/playback`:
   получите свежий `data.sources` непосредственно перед началом воспроизведения.
6. Передайте источник в Media3. Видео загружается напрямую с CDN.

Идентификаторы аниме, серии, перевода и плеера храните как `String` и копируйте
из ответов. Для Retrofit передавайте их как отдельные `@Path` с обычным
кодированием, а поисковый запрос — через `@Query("q")`.
Не составляйте `playerID` самостоятельно: он должен соответствовать выбранной серии.

## Модели и пустые состояния

Все успешные ответы каталога и playback содержат поле `data`. `/health`
возвращает `{"status":"ok"}`. Ошибки имеют вид `{"error":"..."}`.
Пустые списки возвращаются как `[]`, а не `null`; это нормальное пустое состояние.

Поля, отмеченные в Swagger как необязательные, могут отсутствовать. В Kotlin
задавайте им значения по умолчанию, например `val poster: String? = null`.
Неизвестные поля JSON допускайте, чтобы клиент мог работать после расширения API.
`status`, тип аниме и `provider` — строки без закрытого списка значений.
Название серии и тип перевода текущий провайдер обычно не заполняет.

## Media3 и временные ссылки

| `sources[].type` | MIME для Media3 |
| --- | --- |
| `hls` | `application/x-mpegURL` |
| `dash` | `application/dash+xml` |
| `mp4` | `video/mp4` |

Используйте `sources[].url` для `MediaItem` и соответствующий MIME. Для HLS/DASH
подключите соответствующие модули Media3. Применяйте `sources[].headers`, если
поле есть, к HTTP-запросам медиаплеера. AniBoom возвращает HLS/DASH, Kodik — HLS,
CVH — HLS/DASH либо MP4. Дополнительные заголовки в проверенных источниках не нужны.
`quality: "auto"` означает адаптивное качество, выбираемое плеером.
Для нескольких источников Kodik/MP4 CVH список упорядочен от высокого качества
к низкому; покажите выбор пользователю или выберите качество под устройство
и соединение. Например, `"720"` означает 720p, `"1080"` — 1080p.
Некоторые ссылки провайдер привязывает к публичному IP: backend и TV должны
использовать совместимый публичный адрес выхода в интернет.

Playback возвращает `Cache-Control: no-store`. Не сохраняйте URL в истории
просмотра: храните выбранные идентификаторы и позицию, а ссылку получайте заново.
Отсутствие `expires_at` означает неизвестный срок жизни ссылки. Примеры URL
в Swagger синтетические; для просмотра нужен новый ответ playback.
При истечении ссылки можно повторно запросить playback и восстановить позицию;
ограничивайте повторные попытки, чтобы избежать бесконечного цикла.

## Обработка ошибок на TV

| Код | Значение и действие клиента |
| --- | --- |
| `400` | Проверьте запрос и переданные идентификаторы; повтор без исправления не поможет. |
| `404` | Аниме, серия или плеер больше недоступны; обновите соответствующий список. |
| `422` | Плеер не поддерживается или видео недоступно/защищено; предложите другой вариант. |
| `502` | Провайдер временно недоступен или ответ изменился; предложите ограниченный повтор. |
| `500` | Внутренняя ошибка backend; покажите сообщение и возможность повторить позже. |

Сетевой тайм-аут клиента настройте с запасом относительно тайм-аутов backend:
playback может последовательно обращаться к каталогу и плееру. При значениях
по умолчанию `ANIMEGO_TIMEOUT=10s` и `PLAYER_TIMEOUT=10s` общий бюджет
playback составляет до 20 секунд. Отменяйте ненужные запросы при уходе с экрана.

Неизвестные плееры и недоступные выбранные источники возвращают `422`. Защищённое видео
не поддерживается. Главная витрина, фильтры, пагинация API, аккаунты,
избранное и история просмотра в текущем backend не реализованы.
